# Agent 开发的应用类插件思考
目前出现了像 IM 服务的插件，它会引用厂商 SDK，而且一般是需要进程常驻，这种场景下其实就是很类似服务端接口了，我们需要考虑如何设计 Agent 开发的应用类部署，才能保证应用的可靠性和安全性

## 应用类型

### 纯前端应用
1. 就是一个静态资源，最简单的是可以通过 Agent 平台服务代理静态文件
2. 也可以在发布应用后，静态资源自动同步到 CDN 上加快访问

### 包含后端接口
1. 需要访问数据库资源，Mysql、redis、ES 等，这类Agent可以开发，但是数据库的不可控操作很容易导致攻击和故障。所以只支持调用已有接口、本地 CLI 或者 MCP 服务来完成
2. 这部分部署，需要一个容量可伸缩的后端服务容器，容量隔离，安全隔离，网络严格设置白名单访问
3. 不维护登录状态，统一通过 Agent 平台注入的 token 来完成
4. 域名全部走 Agent 平台服务代理
