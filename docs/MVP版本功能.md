## 1. 背景与目标

### 1.1 一句话定义

MVP 交付一个**以“空间”为组织单位的 Web Agent 工作台**：用户在空间内通过对话与 Agent 协作，Agent 能在空间中创建资源（数据库、MCP、工具、UI 组件、LLM Wiki）、操作文件，并在消息中渲染 UI 组件。

### 1.2 MVP 要验证的假设

| # | 假设 | 验证方式 |
| --- | --- | --- |
| H1 | “空间 = 权限边界，目录 = 空间内的真实文件目录”的模型用户能理解，不需要额外的项目/团队概念 | 用户能区分并独立完成建目录、建技能、建会话、分享、收回权限 |
| H2 | 对话建资源（“帮我建个数据库资源”）比表单建资源体验更好 | 场景 1–4 的完成率与耗时 |
| H3 | 消息内联渲染 UI 组件（`@component`）能替代一部分独立页面 | 组件被引用次数、是否有用户主动要求取消该功能 |
| H4 | 公共资源区能解决“资源复用 vs 权限隔离”的矛盾 | 公共资源的被引用数、越权投诉数 |

## 2. MVP 范围

### 2.1 本次交付

| 端 | 交付内容 |
| --- | --- |
| Web 客户端 | 空间管理、会话聊天、资源管理、公共资源页、权限申请与授权、组件渲染 |
| 服务端 | Agent 核心能力、资源管理（含版本/发布/回滚）、组件加载服务、空间管理、权限管理、钉钉 SSO |

### 2.2 明确不做（防止范围膨胀）

- ❌ 多租户 / 多企业（数据模型预留 `tenant_id`，MVP 固定单值）
- ❌ 组织架构与部门管理（人员平铺，仅区分“平台管理员 / 普通用户”）
- ❌ CLI、Electron、A2A 客户端
- ❌ 自定义工具的市场化发布审核（MVP 只做空间内自建自用 + 公共资源由管理员发布）
- ❌ 工具/组件的自动生成流水线（对话生成仅针对资源**配置**，代码级生成留到下一期）
- ❌ 计费与用量账单（仅记录 token 消耗）
- ❌ 审批流走钉钉审批（MVP 用站内通知 + 站内审批）
- ❌ 移动端适配（仅保证 PC 端可用，宽度 ≥ 1280）
- ❌ 空间对外分享链接（仅支持分享给平台内用户）

## 3. 角色与权限

### 3.1 角色定义

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 默认角色。拥有个人空间，可对话、建资源、申请权限 |
| 空间所有者 | 个人空间的所有者；共享空间的创建者。可管理成员与授权、审批申请 |
| 空间成员 | 被分享进共享空间的用户，权限由所有者指定或申请获得 |
| 平台管理员 | 审核公共资源发布、查看全局审计、管理所有空间（仅运维场景） |

### 3.2 权限级别（补充细化）

| 级别 | 可做的事 |
| --- | --- |
| `view` | 浏览空间目录结构与资源清单，**不能看文件内容、不能用资源**（分享默认级别） |
| `read` | 在 `view` 基础上：查看文件内容、下载、查看资源详情、在会话中**使用**该空间的资源 |
| `write` | 在 `read` 基础上：新建/修改/删除文件、目录与技能、新建/删除会话、创建资源、编辑资源 |
| `manage` | 在 `write` 基础上：分享空间、修改成员权限、审批权限申请、删除空间 |

规则：

- 空间所有者对自有空间恒为 `manage`；`manage` 不可被分享出去（避免权限漂移）。
- 个人空间恒为私有，不可分享、不可改为共享（原清单提到“个人空间可改为共享空间”，**建议否决**：直接新建共享空间更清晰，避免误操作泄露个人数据；若坚持保留，需 Owner 二次确认并列出影响）。
- 权限变更即时生效，且 Agent 在会话中的操作立即受新权限约束（每次工具调用前校验，不做会话级缓存）。

### 3.3 Agent 执行身份（补充）

- **Agent 以发起会话的用户身份执行**，不引入独立的 Agent 身份或服务账号。
- 因此 Agent 的能力 = 该用户在该空间链路上的权限交集，Agent 无法越权。
- 会话跨空间引用资源时（例如在个人空间会话中使用公共资源），以用户的直接授权为准，不因空间关系自动放行。
- 所有 Agent 发起的写操作在审计日志中标记 `actor=user`、`on_behalf_of=agent`。

## 4. 核心概念与模型

### 4.1 空间树

树里只有三类节点：**空间**（数据库里的一级空间）、**目录**（文件系统里的真实目录，可多级）、**技能**（带 `.meta.json` 的特殊目录）。会话不占层级，可挂在空间根或任意目录下。

```
个人空间「我的空间」(personal, private)          ← 空间：一级，不可再建子空间
├── 新会话                                        ← 会话（默认生成，挂空间根）
├── 设计/                （目录：可多级，可建会话）
│   ├── 新会话
│   └── 原型/            （子目录）
├── 代码助手/            （技能：含隐藏 .meta.json，图标不同）
│   ├── 新会话
│   └── 提示词/          （技能内的子目录）
└── 学习笔记/            （目录）
    └── 素材/

共享空间「数据平台组」(shared, 可分享)
├── 新会话
└── 生产配置/            （目录，权限沿用空间）
```

约定：

- 空间**只有一级**（子空间概念已取消）：空间之间没有父子关系，第二层起全部是目录。
- **资源归属**：资源属于创建它的空间；该空间的成员权限决定谁可以使用其中的目录、文件与会话。
- **可见性**：成员默认可见空间内全部目录与会话，不再有“父空间/子空间”的继承链。
- 删除空间：软删（进入回收站，保留 30 天），存储目录 `Rename` 到 `trash/{ts}/{space_id}/`；删除前校验“无存活资源引用、无其他成员”或要求确认级联影响。
- 空间重命名允许，但**物理路径不变**（用 `space_id` 作为物理目录名，名字只是展示属性），避免路径与权限引用失效。
- 目录名即真实路径名，改名/删除都直接作用于文件系统（不进回收站），目录最多 5 层。

### 4.2 空间、目录与技能

| 维度 | 空间（space） | 目录（directory） | 技能（skill） |
| --- | --- | --- | --- |
| 存储 | PostgreSQL `space` 表 | 只存在于文件系统，不落 `space` 表 | 目录 + 目录内隐藏的 `.meta.json` |
| 层级 | 只有一级，无父子空间 | 可多级（最多 5 层） | 与普通目录同级，同样可建子目录与会话 |
| 默认会话 | 创建时自动生成一个「新会话」 | 无默认会话，可手动「新建会话」挂在目录下 | 同左 |
| 权限 | 独立成员与权限（view/read/write/manage） | 沿用所属空间权限，不可单独分享 | 同左 |
| 物理路径 | `spaces/{space_id}/` | `spaces/{space_id}/files/{a}/{b}` | 同目录，额外含 `.meta.json` |
| 删除 | 软删进回收站，级联内容 | 直接删除，不进回收站；目录内会话移回空间根 | 同左 |
| 重名 | 允许重名（以 ID 区分） | 同级不允许重名 | 同级不允许重名 |

`.meta.json` 由后端写入，前端不直接编辑：

```json
{ "name": "代码助手", "description": "……", "type": "skill", "created_at": "2026-11-03T08:00:00Z" }
```

创建入口：

- 左侧树顶部的「+」只用于新建一级共享空间。
- 空间节点上的「+」下拉：**新建目录 / 新建会话 / 新建技能**。
- 目录（含技能）节点上的「+」下拉：**新建会话 / 新建目录**；「…」菜单：**重命名 / 删除**。
- 新建技能需要 `write` 及以上权限，创建后目录名即真实路径，`.meta.json` 中的 `name` 作为展示名。
- Agent 可见的技能与工具定义 = **当前空间 + 系统空间**，同名以当前空间为准（用户定制的版本覆盖平台默认）；空间文件根的隐藏索引 `.meta.json` 汇总本空间的 skills / tools / mcps，供加载与技能选择器使用（该文件是平台保留项，用户与 Agent 不可见、不可读写）。
- 技能有两处生效：每轮对话注入技能索引（名称 + 描述 + 路径，正文按需读取）；会话可绑定一个技能，把 SKILL.md 正文直接注入当轮提示词。

会话与空间/目录的关系：

- 会话归属空间，并可额外指定所属目录（`session.dir`，相对 `spaces/{space_id}/files/`）；`dir` 为空表示直接挂在空间根。
- 左侧树把会话渲染在其所属目录节点下；目录改名时会话路径同步迁移，目录删除时会话移回空间根而不是被删除。
- **文件节点**：目录下的文件（平台保留的隐藏项除外）都作为叶子节点展示在树中，路径限定在该空间 `files/` 下。清单里每个文件同时带 `previewable`（能否读正文，`file_read` 认它；引用不限类型，非文本按附件进清单）与 `preview_kind`（面板渲染方式），面板按 `preview_kind` 分四类：`text`（**除媒体与已知二进制之外的一切文件**——代码、配置、`Makefile` / `Dockerfile` 这类无扩展名文件都在内，判定见 `Readable` / `previewKind` 的排除法，走正文端点）、`image` / `video` / `audio` / `pdf`（浏览器能原生渲染，走 raw 端点内联展示，视频靠 `Range` 支持拖动进度）、`none`（压缩包、可执行产物等，给出「该文件类型不支持预览」+「下载到本机」）。raw 端点的 MIME 是**服务端固定白名单**（不靠系统探测，也不认后缀以外的信号），只放行不会执行脚本的容器：HTML / XML / JS 不进 raw 白名单（它们作为源码走文本预览，转义后渲染，不会被当成可执行文档内联返回）；SVG 允许但响应头带 `CSP: sandbox`，直接打开也拿不到平台 Cookie 与 localStorage。接口为 `GET /spaces/files`（清单）、`GET /spaces/{id}/file?path=`（正文，只认可预览类型、超 256KB 截断；扩展名不认识的文件按 8KB 取样做二进制嗅探，含 NUL 回 `400 not_text_file`，面板据此退回下载）、`GET /spaces/{id}/file/raw?path=`（浏览器渲染用的原始字节，白名单 MIME + `inline` + `Range`）与 `GET /spaces/{id}/file/download?path=`（原始字节，不截断，`Content-Disposition: attachment` + `octet-stream`，中文名走 RFC 5987）。
- **上传与引用**：两个上传入口共用 `POST /spaces/{id}/files`（multipart，可选 `dir`；**不限类型**，图片 / 音视频 / PDF / 压缩包都能传，单个 ≤ `UPLOAD_MAX_FILE_MB`（默认 100MB）、一次 ≤ 10 个；同名自动追加 `-1`、`-2` 后缀，不覆盖已有文件）。类型差异只在**读取侧**：文本能被 `file_read` 读出正文，其余类型只能预览或下载——引用本身不限制类型，非文本作为**附件**进清单，服务端在清单提示里明确「不提供正文读取、不要调用 `file_read`」，避免模型换来一次失败回执——会话输入框传到当前空间（会话挂在目录下时落在该目录，上传成功即加入本轮引用，非文本在标签上标「附件」）；文件树里空间与目录的「+」菜单选「上传文件」则直接落到该空间根或该目录（只读的已安装插件目录没有入口）。引用文件以路径随消息提交（`POST /sessions/{id}/chat` 的 `references`，最多 20 个），服务端校验后把清单以固定标记块（`[引用文件]`）拼进用户消息落库：清单行只写纯路径（前端据此渲染文件标签），可读性要求写在清单之后——文本要求 `file_read`，非文本明确不可读。输入框里直接打 `@` 也能就地搜索并引用：`@` 之后到光标前没有空白即按文件名/路径过滤，回车或点击选中，正文里的 `@query` 会被删掉并换成引用标签。引用只做存在性校验、不预读正文，避免一条消息把大文件塞进上下文。

### 4.2.1 系统空间（system）

平台内置一个全局唯一的「系统空间」，**只有系统管理员可见、可编辑**：

- 管理员识别：配置 `ADMIN_JOB_NUMBERS`（逗号分隔工号）。MVP 用配置文件，后续接入组织架构后改为角色表。
- 初始化：服务启动或管理员首次登录时按工号初始化，幂等；其他用户的空间列表里完全看不到它。
- 系统空间同样是 `space` 表中的一条记录（`type='system'`、`is_system_reserved=true`），不可重命名、不可删除，成员权限固定为 `manage`。
- 固定包含一个默认会话，以及三个**内置目录**：

| 目录 | 用途 | 约束 |
| --- | --- | --- |
| `files/skills` | 全局技能：每个技能是带 `.meta.json` + `SKILL.md` 的目录 | 目录本身不可改名/删除；技能内容可编辑 |
| `files/tools` | 内置工具定义（与运行时 `BuiltinManifests()` 同步，一个工具一个 JSON） | 同上 |
| `files/mcps` | MCP 服务快照：`README.md` + 每个已注册服务一个 JSON | 同上 |

- `skills` / `tools` / `mcps` 三个目录是 **Agent 默认全局可见的能力搜索源**：所有用户（不限空间）都可读取，Agent 通过 `plugin_search` 检索、`plugin_read` 读取具体文件（插件总量不设上限，不提供全量列举）。
- 内置内容只在文件缺失时写入，不覆盖管理员后续的修改。
- 内置内容初始包含：空间管理、文件与目录操作、会话管理三个技能说明，以及全部内置工具（时间、资源列表、会话列表、文件列表、文件读写、全局能力源）的定义快照。`tools/` 属于平台托管内容，每次启动按运行时清单覆盖写入，保证与 `BuiltinManifests()` 一致。

### 4.3 文件系统映射（MVP 用本地 FS）

**已定（原 §11 Q1）**：

- **MVP 阶段不引入 HDFS**，一律使用本地文件系统；部署阶段再切 HDFS / S3。
- 空间树、权限、资源元数据**始终存 PostgreSQL**；文件系统只承载文件内容与资源产物（HDFS 不适合高频元数据操作：小文件、海量目录、无事务、rename 代价高）。
- 所有读写经 `Storage` 接口抽象，**业务代码不得直接使用 `fs` 包**：

```go
type Storage interface {
    Put(ctx context.Context, key string, r io.Reader, size int64) (string, error)
    Get(ctx context.Context, key string) (io.ReadCloser, error)
    Delete(ctx context.Context, key string) error
    List(ctx context.Context, prefix string) ([]Entry, error)
    Rename(ctx context.Context, from, to string) error
    Stat(ctx context.Context, key string) (Entry, error)
}
```

MVP 实现 `localFS`（根目录可配 `STORAGE_ROOT`），后续加 `hdfs`、`s3` 实现，通过配置切换，不改调用方。

目录布局（`key` 前缀，与存储实现无关）：

```
autoagent/                                  # 存储根
├── spaces/{space_id}/                      # 空间物理目录用 ID，改名不影响路径
│   ├── files/                              # 用户与 Agent 的文件区
│   │   ├── plugins/{slug}/                 # 插件草稿 / 安装副本
│   │   ├── 实验数据/                        # 「新建目录」直接落在这里，fs 中可见、名字即目录名
│   │   └── 报表.xlsx                        # 文件
├── published/{kind}/{slug}/{version}/      # 发布件（只读、不可变）
└── trash/{ts}/{space_id}/                  # 回收站：只放被删除的空间目录
```

注意：`files/` 下的目录是**真实的 fs 目录**，可以在存储根目录直接看到、直接用系统工具操作；与 `space` 表中的空间不是一回事。技能目录额外包含隐藏文件 `.meta.json`（`type: "skill"`），普通目录没有。

本地 FS 的两个额外约定（切 HDFS 时一并保留）：

1. `key` 一律用正斜杠、禁止 `..` 与绝对路径，由 `localFS` 做路径规范化与越界校验，防止目录穿越。
2. 单机多副本部署时本地 FS 不共享 → MVP 限定**单实例或共享卷（NFS/PVC）部署**；需要多副本时切对象存储，这是部署期必须触发切换的条件之一。

### 4.4 插件模型

平台没有「资源」：数据库、MCP 服务、目录都不再抽象成可授权对象，也不再有自己的版本与公共区。所有可复用件统一成插件，六类 `kind`：

| kind | 说明 | 版本化对象 |
| --- | --- | --- |
| `skill` | 指令包（`SKILL.md` + 参考文件） | 文件快照 |
| `tool` | 工具（清单 + 入口脚本 + `evals.json`） | 清单 + 脚本 |
| `mcp` | MCP 服务（清单里的 `transport` + 工具列表） | 清单 |
| `component` | 前端组件（`ui.json` 声明式 DSL） | 清单 + DSL |
| `agent` | 智能体（`AGENT.md` 提示词 + 继承关系） | 清单 + 提示词 |
| `source` | 搜索源（`search.json` 或 plan/map 脚本） | 清单 + 脚本 |

生命周期：草稿（`files/plugins/<slug>/`，可编辑）→ 发布（系统管理员，`published/{kind}/{slug}/{version}/` 不可变快照）→ 安装到目标空间（写 `plugins/<slug>/` 只读副本）→ 启用。**安装/启用就是授权**，没有 `tool_binding`、没有 `resource_grant`。

- 版本化的是**清单与文件内容**，每个版本不可变；回滚等于重新发布旧内容为新版本。
- **发布不改动外部系统里的数据**：清单里的连接配置只是一段声明，改版本不会回滚远端库表。
- 系统空间安装 = 全局可用；普通空间安装只对该空间生效。
- 撤销 = 停用（`plugin_install.status=disabled`，四条读取路径同时生效）或卸载；审计永久保留。

### 4.5 术语对齐

本 PRD 与技术方案保持一致的术语，避免两套说法：

| PRD | 技术方案 |
| --- | --- |
| 技能 / 工具 / MCP / 组件 / 智能体 / 搜索源 | `Plugin`（`kind` 对应） |
| 插件被 Agent 使用 | 插件安装/启用 → 工具进 `Tool.Registry`（无绑定层） |
| 公共可见 | 系统空间安装（全局）或发布件对其他空间可见 |
| 会话 | `session` / `run` |

| 试运行 | `plugin_try` 在沙箱里真实跑一次（脚本 / MCP / 搜索源同一入口），回执里的 `top_keys` 提示 `items` 路径怎么写 |
| 发布 | 系统管理员把草稿发布为不可变快照（`published/{kind}/{slug}/{version}/`）；`kind=tool` / `kind=agent` 发布前跑 `evals.json` 断言 |
| 安装 | 空间管理员安装到本空间（写 `plugins/<slug>/` 只读副本），**安装即授权**；系统空间安装 = 全局可用 |
| 启停 | 空间管理员启用/停用；停用在四条读取路径上都生效（加载快照、检索合并、内置工具注册、搜索源注册） |
| 审批设置 | 插件卡片可改「需确认命令」（仅 `shell.exec`）；出网非 GET/HEAD 固定确认，fs 写与空间内删除不确认 |
| 卸载 | 只移除本空间的安装与工具注册，不删审计，不动发布件 |
| 文件 | 空间内支持新建文件夹、上传、下载、重命名、移动、删除、在线预览（文本/图片）；单文件上限 100MB |
| 验收 | ① 未安装的插件工具不出现在会话工具列表；② 安装后立即可用，不需要第二次授权；③ 停用后检索与调用同时失效；④ 卸载后审计仍可查 |

### FR-7 前端组件加载服务与消息内渲染

| 项 | 内容 |
| --- | --- |
| 组件模型 | 每个组件 = `plugin.json`（slug、名称、描述、`data_sources` 声明）+ `ui.json`（`wa-ui/1` 声明式 DSL）；引用已安装插件工具取数，DSL 里不出现工具名、URL 与凭据 |
| 构建 | **无构建**：两份 JSON 直接存 `Storage`（**MVP 本地 FS**），按 `slug@版本` 不可变寻址；DSL 在 dry-run / 发布 / 读取时校验 |
| **生成方式** | 组件由平台内置 Skill `builtin_plugin_dev`（组件子手册）对话式生成（追问 → 生成 `plugin.json` + `ui.json` → dry-run 校验 → 预览 → 发布 → 安装）。**Skill 有版本、可升级**；生成规则变了发新版 Skill，渲染节点变了发新版平台 |
| **渲染协议** | 消息内容为**结构化内容块数组**，组件以 `ui` 块表达，**不在正文里写版本号**：<br>`{"type":"text","text":"本月销售情况如下："}`<br>`{"type":"ui","component":"sales-dashboard","version":"1.2.0","props":{"period":"month"},"fallback":"[销售看板]"}` |
| **版本由后端注入（本期确认项）** | 模型只输出组件 slug；服务端在持久化消息前解析版本并写入 `version` 字段：优先取「会话创建时锁定的组件版本」，无锁定时取当前 published 版本。**禁止模型自行书写版本号**；模型输出中的组件引用块会被服务端覆写为解析结果 |
| **版本快照落库** | `message.component_refs` 固化 `{component, version, props, resolved_at}`，作为会话历史的一部分永久保留；历史消息永远按当时版本渲染，组件升级或下架都不影响既有消息 |
| 前端行为 | 前端**不解析正文文本**，只渲染结构化块；不做正则扫描，避免与 `@提及`、代码块、Markdown 语法互相干扰 |
| 文本降级 | 纯文本客户端（CLI、导出 Markdown）使用 `fallback`；需要行内引用时统一写作 `@component(slug)`（**不带版本**），块级用 `:::component{#slug}`（remark-directive），**一律不使用 `&` 分隔版本**（`&` 会被 HTML 实体与 Markdown 管道改写） |
| 流式 | 先发 `ui.placeholder` 占位事件，props 就绪后 patch 为完整块，避免布局跳动 |
| **来源封闭** | 只接受平台 Skill 生成 + 审核发布的组件；**不提供上传、导入或引用外部组件的能力**，组件只能是白名单 DSL 节点 |
| **渲染容器（不用 iframe）** | 组件是声明式 DSL（`wa-ui/1`），由宿主原生 React 节点渲染；没有可执行 JS/CSS，样式全部来自宿主 Token，**无 iframe 裁剪问题、无独立文档加载、无样式注入** |
| **执行隔离** | 组件没有可执行内容：无 JS/HTML/CSS 注入点，绑定只允许 `{{state.x}}` / `{{props.x}}` / `{{data.<id>.x}}`，动作为白名单枚举；节点/字段写错直接校验失败 |
| **数据通道** | 组件不发请求：`data.<id>` 由宿主转成 `POST /spaces/{id}/plugins/{slug}/data`，后端校验 `data_sources` 白名单 + 用户权限，经 `Invoker`（凭证注入、审批、审计）执行 |
| **浮层** | 组件不自己实现浮层：DSL 只提供宿主节点，浮层由宿主组件库渲染（Card/Alert 等），几何上不会被消息容器裁剪 |
| **加载性能** | 一次 `GET .../ui` 拿到 `{manifest, dsl, height}`，无 JS 加载、无 importmap、无预取；历史版本读不可变发布件，天然可缓存 |
| 降级 | 组件加载失败/超时/无权限 → 显示占位卡片 + 错误原因 + 「重试」，不阻塞消息阅读 |
| 验收 | ① 组件渲染无 iframe、无独立滚动条，主题切换即时生效；② 组件升级到新版本后历史消息仍渲染原版本；③ 引用未安装组件时显示占位卡而不是空块；④ DSL 越界（未声明数据源、未知节点、表达式）被拒绝并提示位置；⑤ 写数据源必须用户点击且带 `confirm`，只读权限用户伪造手势也被后端拒绝并记审计；⑥ 组件触发 `message` 只填充输入框、不自动发送；⑦ 导出 Markdown 降级为 `fallback` 文本不报错 |

### FR-8 Agent 核心能力与 Skill

| 项 | 内容 |
| --- | --- |
| 能力 | 多轮对话、工具调用、流式输出、思考过程输出、上下文管理（超长会话压缩）、错误重试 |
| 对话页用量可见（2026-11） | 输入框与发送按钮合并为一行（按钮嵌在输入框右侧），流式期间实时显示本轮已用时；助手消息卡片展示这一轮的 token 消耗（输入 ↑ / 输出 ↓）与总耗时，随消息落库（`message.in_tokens` / `out_tokens` / `duration_ms`），刷新后仍可见。思考块折叠标题同样标出这一段思考的耗时（`message.parts` 里 reasoning 段的 `duration_ms`）：正在想的那一段实时数秒，想完后用落库值，与工具卡耗时同一口径 |
| 对话正文与输入区（2026-11） | 助手回答按 **Markdown** 渲染成有样式的正文，复用仓库既有的轻量渲染器（`web/src/components/Markdown.tsx`，与文件预览同一套 `md-*` 样式）：标题、有序/无序列表、表格、代码块（带语言标签）、引用、分割线、粗体、行内代码、外链；**不引入第三方解析器、不用 `dangerouslySetInnerHTML`**（原始 HTML 按纯文本输出，没有脚本注入面），外链新窗口打开。用户消息保持纯文本、按原样换行。输入框默认一行、上下间距与发送按钮一致，**拖拽上边框**可调整高度（双击恢复自动高度），内容变多仍自动增高，到上限后改为框内滚动 |
| └ 已知差距 | 该渲染器不支持嵌套列表（平铺成同级列表）、任务列表、斜体、图片与自动链接；需要完整 CommonMark 时按组件注释替换为 marked/markdown-it |
| 编排实现可切换（2026-11） | 契约在 `internal/agent`（`Agent` 接口 + §7.3 事件协议），实现：`internal/agent/builtin`（ReAct，默认）、`internal/agent/direct`（无工具直答）；`AGENT_IMPL` 切换，未知实现回退 builtin，`GET /agent/info` 返回当前实现与能力，`run.budget.impl` 留痕。平台侧（审批判定、checkpoint、压缩、预算、SSE 契约）不因实现而变。差距：断点续跑（`Capabilities.Resume`）只声明未实现；审批只推 `approval.req`，没有审批记录与恢复入口；模型 failover 由 ModelRouter 提供，尚未按实现区分 |
| 平台部署事实 | 租户（企业）名称、IM 接入方与登录是否已配置、当前用户（姓名/工号）与所在空间，由会话层填入系统提示词的 `## 平台（部署事实）` 段，**不做成工具**：这类信息必须恒真，而模型对「公司用什么 IM」有强先验，做成工具它会顺着猜而不调用，工具 schema 还要每轮常驻。任一字段拿不到时整段省略，模型如实说不知道；智能体设定只能排在其后，不能改写 |
| 当前时间（2026-11） | 系统提示词最前面注入 `## 当前时间`（用户本地时间 + 星期 + 时区名与数字偏移 + UTC），**不再有 `time_now` 工具**：模型对「今天几号」有训练期先验，做成工具它会不查就答，而「今天」是每轮对话的前提。来源优先用户端——前端每次对话随 `client_time`（RFC3339，本地墙上时间 + 偏移）与 `timezone`（IANA 名）上报，`resolveClock` 解析后按用户时区渲染；取不到（任务回执、外部集成）才回落服务器时间，并在该段写明「这是服务器时间，可能与其所在时区不同」。每轮重新注入，不是会话创建时的快照；子 Agent 继承父级那一份。修的是「UTC+8 的凌晨被答成昨天」：服务端按自己的时区算，日期天然差一天 |
| 内置工具 | `space_list`、`session_list`、`fs.list` / `fs.read` / `fs.write`、`skill.create`、`plugin_search` / `plugin_read`。文件能力**只作用于会话所属空间**的 `files/` 下：路径禁止 `..`/绝对路径与平台保留的隐藏项（`.meta.json` / `.install.json` / `.history`），只放行 md/json/txt/yaml 与用户自己的隐藏配置（`.env` 等），读 24KB、写 256KB 上限；`fs.write` / `skill.create` 风险 L3 但副作用限定为 `write-workspace`，按空间 `write`/`manage` 权限放行，外部资源写入仍需绑定 + 审批。`skill_create` 复用 `space.CreateSkill`（名字校验、`.meta.json` 与 UI 新建技能一致），再写符合 Agent Skills 规范的 SKILL.md（frontmatter + 入口流程），上限 64KB。`plugin_search` 按关键词检索插件（无上限，不提供全量列举），`plugin_read` 读取正文并支持分页 |
| Skill | MVP 内置 4 个：`创建数据库资源`、`创建 MCP 服务资源`、`find/创建工具资源`、`创建 UI 组件资源`；每个 Skill 定义询问参数清单与校验规则 |
| **Skill 作为一等资产** | Skill 有独立版本，复用 Agent 的版本/发布/灰度/回滚机制；生成规则（组件白名单、禁止 API、追问话术、模板库）写在 Skill 里而非硬编码；**MVP 先交付可用版本，上线后直接在产品内迭代优化**，每轮优化产出新版本并对比“生成一次通过率” |
| 搜索 | 空间内文件名搜索 + 会话标题搜索（MVP 不含全文检索） |
| 验收 | ① 4 个 Skill 均能通过自然语言触发并收集齐参数；② 缺少必填参数时 Agent 会追问而非报错；③ 参数非法（如端口超范围）时给出修正提示 |

## 6. 关键场景（含异常分支）

### 场景 1：对话创建数据库资源

1. 用户在个人空间「会话」中新建会话，输入“帮我创建一个数据库资源”。
2. Agent 命中 `创建数据库资源` Skill，依次询问：资源名、数据库类型、host、端口、库名、用户名、密码（输入框不回显）。
3. 用户填写（可纠正），Agent 复述参数摘要并请求确认。
4. 用户确认 → 服务端创建 `db` 资源（v1.0 草稿）→ 自动执行连接测试。
5. 测试通过 → 自动发布 v1.0，Agent 在消息中返回资源卡片（名称/类型/状态/测试结果），并提供「在空间中查看」。
6. 资源出现在该空间资源列表与文件树同级展示位置。

异常分支：

- 连接测试失败 → Agent 说明失败原因（认证失败/网络不可达/库不存在），询问是修改参数重试还是保存为草稿。
- 用户中途说“先不建了” → 结束流程，不产生资源。
- 用户提供明文密码在消息中 → 允许（MVP），但消息中密码字段在展示与日志中脱敏。

### 场景 2：对话创建 MCP 服务资源

参数：MCP 服务名、端口、访问路径、传输方式（stdio/SSE/streamable HTTP）、认证方式。流程同场景 1，连接测试改为“拉取 `tools/list` 成功即视为通过”，并展示发现到的工具数量。

### 场景 3：对话创建/安装工具资源

1. 用户输入“帮我创建一个工具资源”。
2. Agent 先用 `find` Skill 检索已有工具与公共工具，返回候选：命中则询问“是否直接安装”；未命中则进入创建流程。
3. 创建流程询问：工具名、工具类型（内置能力/HTTP/Python 脚本）、描述、参数（名称/类型/是否必填/说明）。
4. 生成工具目录与定义文件，写入空间 → 资源卡片展示 → 可在本空间会话中被调用。

异常：参数 Schema 非法（必填缺类型）→ 提示具体字段；工具类型不支持 → 列出支持的类型。

### 场景 4：对话创建 UI 组件资源

1. 用户输入“帮我创建一个前端 UI 组件资源”。
2. Agent 询问：组件名、类型（图表/表格/表单/卡片/自定义）、描述、props 参数。
3. 创建组件资源与 manifest（含 props Schema、依赖数据源声明、最大高度、是否使用浮层）。
4. 用户在会话中说“用组件展示一下”，Agent 输出组件引用 → **服务端解析版本并写入消息的结构化 `ui` 块** → 前端按该版本加载并渲染。
5. 组件在空间中可见、可编辑 manifest、可发布到公共区（走 FR-6 审核）。

异常：组件渲染失败 → 消息内展示占位卡与错误；依赖数据源未授权 → 提示去申请权限；组件被下架 → 历史消息仍按已记录的版本渲染（若产物已删除则降级为 `fallback` 文本并提示原因）。

## 9. 非功能需求

### 9.1 性能

| 指标 | 目标 |
| --- | --- |
| 页面首屏（工作台） | P95 < 2s（内网） |
| 空间树 / 资源列表 | P95 < 500ms（1000 资源量级） |
| 消息流首 token | 平台侧额外开销 < 300ms |
| 并发会话 | 100 并发 run 起步，可水平扩展 |
| 文件上传 | 100MB 文件成功率 99%，支持断点续传（P1 可选） |

### 9.2 配额与限制（补充）

| 项 | 限制 |
| --- | --- |
| 空间数量 | 每人共享空间上限 20 个 |
| 空间树深度 | 3 层 |
| 单文件大小 | 100MB |
| 单空间容量 | 默认 5GB（可配） |
| 会话消息数 | 单会话 2000 条，超出提示新建会话 |
| 单次运行 | 工具调用 ≤ 20 次，token ≤ 60k，时长 ≤ 5 分钟 |
| 组件包 | ≤ 200 文件 / 5MB，`ui.json` ≤ 64KB、≤ 300 节点 |

### 9.3 安全与审计（补充）

- 会话消息中的密码类字段展示与日志双重脱敏。
- 高危操作（建资源、删文件、写 SQL）必须经过会话内确认并记审计。
- 审计最小集：登录/登出、空间增删与分享、权限变更与审批、资源增删改与发布回滚、Agent 工具调用（含参数摘要）、文件上传下载。
- 组件渲染：声明式 DSL（`wa-ui/1`）+ 宿主原生渲染，无 JS/HTML/CSS 注入点，取数只经宿主与 Invoker，不使用 iframe。

### 9.4 可用性与降级

- LLM 不可用：会话可继续查看历史，发送时明确提示并保留草稿。
- 存储不可用（本地盘/共享卷异常）：文件操作报错并给出重试；会话与资源列表仍可用（元数据在 PG）。
- 组件服务不可用：消息中组件降级为占位卡。

## 附录 A：原始需求记录（保留原样）

> 你先实现一版 MVP web agent client 和 service，
> 客户端包括功能：
> 1. 实现一个空间管理功能，一个空间对应一个文件系统中的目录。服务端选型用 hdfs。默认是用户个人空间，且空间只能自己读写。可以创建和删除新空间（目录），也可以分享给别人。空间分为个人空间（默认类型，可以改为共享空间）和共享空间，个人空间只能自己查看，共享空间可以分享给别人查看（默认只能看见目录没有读写权限，读写权限需要申请或者手动指定）。
> 2. 每个空间有个默认子空间「会话」，该目录不可删除和修改，在会话空间下聊天交互会话，在其它子空间可以继续创建子空间，可以新增资源（数据库、MCP、工具、前端 UI 组件、Skills、LLM wiki等），这些资源默认在当前空间和子空间下可使用。子空间中也可以新建任何形式的文件（AI Agent 也可以在有空间权限的情况下操作）。
> 3. 每个会话对应一个 agent 聊天交互界面，功能点和交互效果参考 codex、deepseek harness 这些工具。例如需要有思考过程展示、有工具调用过程和结果提示
> 4. 实现一个「公共资源」的独立页面，该页面展示了所有有权限的资源，包括（数据库、MCP、工具、前端 UI 组件），这个公共资源，可以被任何空间下的 Agent 使用
> 5. 支持钉钉 sso 登录，需要什么东西你跟我说，我去弄
>
> 服务端包括功能：
> 1. Agent 核心能力
> 2. 资源管理（数据库、MCP、工具、前端 UI 组件、文件目录）：公共资源需要单独管理，有版本和发布历史管理，可以回滚
> 3. 前端组件加载服务，支持会话页面动态加载前端组件
> 4. 空间管理：初始化默认空间、创建和删除新空间、分享给别人
> 5. 权限管理：支持资源设置访问权限
>
> 一些使用场景：
> 1. 用户在个人空间会话下，告诉 agent 帮我创建一个数据库资源，agent 根据创建数据库资源 Skill，询问用户数据库名、用户名、密码、端口等信息，用户填写后，agent 在个人空间下创建数据库资源，并将资源信息在空间中展示。
> 2. 用户在个人空间会话下，告诉 agent 帮我创建一个 MCP 服务资源，agent 根据创建 MCP 服务资源 Skill，询问用户 MCP 服务名、端口、访问路径等信息，在个人空间下创建 MCP 服务资源，并将资源信息在空间中展示。
> 3. 用户在个人空间会话下，告诉 agent 帮我创建或者安装一个工具资源，agent 根据 find skill 和 创建工具资源 Skill，创建工具目录，询问用户工具名、工具类型、工具描述、工具参数等信息，在工具目录下创建工具资源，并将资源信息在空间中展示。
> 4. 用户在个人空间会话下，告诉 agent 帮我创建一个前端 UI 组件资源，agent 根据创建前端 UI 组件资源 Skill，询问用户前端 UI 组件名、前端 UI 组件类型、组件描述、组件参数等信息，在个人空间下创建前端 UI 组件资源，并将资源信息在空间中展示。Agent 可以在消息中通过 @compnent:组件名&v1.0 的方式调用组件，组件会被渲染到消息中。
