# 插件安全基线：发布扫描 + 运行时隔离

本文是插件安全的两道闸门的设计依据，细化《技术方案》§8（安全设计）与《插件体系设计》§6（风险与权限）、§7（执行器）。**实现与本文冲突时以本文为准；本文需要变更时先改文档。**

两道闸门的分工：

| 闸门 | 时机 | 目标 | 失败后果 |
|---|---|---|---|
| **发布扫描** | `publish` 时 | 已知漏洞（CVE）、提示词风险、硬编码凭证、禁用 API | 拒绝发布，草稿可改 |
| **运行时隔离** | 每次执行 | 文件读写越界、网络外联、资源耗尽 | 本次调用失败，进程被回收 |

前提：**私有化部署，无多租户**。因此不做跨租户隔离、不做微虚拟机、不做侧信道防护；威胁模型是「被提示注入的模型 + 有 bug 的同事代码 + 内部人员误操作」，不是「匿名互联网攻击者」。

## 1. 发布扫描

### 1.1 扫描对象与规则类型

| 类型 | 输入 | 规则形态 | 能否阻断 |
|---|---|---|---|
| `prompt` | `SKILL.md` / `AGENT.md` / 任何 `.md` | 正则（多语言） | 可配置 |
| `secret` | 全部文本文件 | 正则 + 熵检测 | **阻断** |
| `code` | `*.ts` / `*.js` / `*.json` | 正则（v1）/ AST（P2） | **阻断** |
| `dep` | `deno.lock` / `package-lock.json` / `node_modules/*/package.json` | 漏洞库匹配 | 可配置 |

明确不做：LLM 语义复核（v1）、二进制扫描、镜像扫描（P2）、许可证合规。

### 1.2 规则集：可热更新，不重启

规则是**外部数据**，不是编译进二进制的常量。

```text
{STORAGE_ROOT}/scan-rules/
  ├── active.json            # {"version": "2026.11.1", "sha256": "..."}
  └── 2026.11.1/
      └── rules.json
```

`rules.json` 结构（一份文件装全部规则，按 `kind` 分派）：

```json
{
  "version": "2026.11.1",
  "rules": [
    {
      "id": "PROMPT-IGNORE-INSTRUCTION",
      "kind": "prompt",
      "severity": "high",
      "blocking": true,
      "pattern": "(忽略|无视|忘记)[^。\\n]{0,8}(之前|以上|前面|先前)的?(所有)?(指令|指示|规则|要求)",
      "message": "提示词要求模型忽略既有指令，可能被用于覆盖平台基础规则",
      "ref": "OWASP LLM01"
    },
    {
      "id": "CODE-FORBID-EVAL",
      "kind": "code",
      "severity": "critical",
      "blocking": true,
      "pattern": "\\b(eval|new\\s+Function)\\s*\\(",
      "message": "插件代码不得使用 eval / new Function"
    },
    {
      "id": "SECRET-AWS-AK",
      "kind": "secret",
      "severity": "critical",
      "blocking": true,
      "pattern": "\\bAKIA[0-9A-Z]{16}\\b",
      "message": "检测到 AWS Access Key"
    }
  ]
}
```

**加载与热更新**

- `ScanEngine` 持有一个 `atomic.Pointer[RuleSet]`，一次扫描只读一次指针，不会读到半更新状态。
- 后台 goroutine 每 30s 检查 `active.json` 的 mtime + sha256；变化则加载、校验、原子替换。也可由 `POST /admin/scan/rules/reload` 立即触发。
- 加载失败（JSON 坏、正则编译失败、id 重复）**保留旧规则**并告警 `scan.rules.invalid`，**不阻断发布**——规则更新不能成为发布渠道的单点故障。
- 每次扫描把 `rules_version` 写进报告，任何结论都能追溯到「哪一版规则判的」。

规则下发：管理员上传（`PUT /admin/scan/rules`，一次一份 `rules.json` + version），落盘后自动生效。私有化环境不走外网拉取；需要 git 同步的客户由运维把文件放进该目录，热加载照样生效。

### 1.3 CVE 扫描

**输入**：包里的 lockfile。没有 lockfile 就**没有 SBOM，扫描无从谈起**，因此：

- 有 `deno.lock` → 解析 npm 段得到 `[{name, version}]`；
- 有 `package-lock.json` → 解析 `packages` 段；
- 都没有 → 报告 `status=skipped, reason=no-lockfile`，**不阻断**，但市场里标记「未扫描」。

**两种数据源**（这是私有化必须做的分叉）：

| 模式 | 数据来源 | 适用 |
|---|---|---|
| `remote` | `POST https://api.osv.dev/v1/querybatch` | 有外网出口的部署 |
| `local` | `{STORAGE_ROOT}/osv/*.json`，OSV 官方 zip 镜像，管理员定期导入 | **私有化默认** |

判定：`SCAN_OSV_MODE=remote|local|off`，`off` 一律 `unscanned`。**扫描不可用时不阻断发布**——否则没有外网的客户永远发不了版本，等于把安全闸门变成业务故障。

**阻断策略（窄口径，否则一定被关掉）**：

```text
阻断 = severity >= high 且 存在 fixed 版本 且 包在运行期可达（非 devDependency）
其余 → 告警
```

无修复版本的漏洞只记录。豁免走 `plugin_scan_allow`（见 1.5），必须写原因与过期时间。

### 1.4 提示词扫描 v1 规则集

只做**确定性、可解释、可离线**的正则，五类（后续按需扩充）：

| 类别 | 示例模式 | 严重度 |
|---|---|---|
| 指令覆盖 | 「忽略之前的指令」「ignore previous instructions」 | high |
| 角色越狱 | 「你现在是…没有限制」「开发者模式」「DAN」 | medium |
| 凭证外泄 | 把 `{{secret}}` / 环境变量拼进 URL 或 `curl` 命令 | **critical** |
| 免确认执行 | 「无需确认直接执行」「不需要征求用户同意」+ 危险动词 | high |
| 危险动作 | `rm -rf /`、`DROP TABLE`、`git push --force`、`--no-verify` | high |

`secret` 类单独一路：AK/SK、GitHub PAT、`sk-`、私钥块 `-----BEGIN`、JWT 字面量、高熵字符串。

命中信息统一为 `{rule_id, file, line, column, snippet(脱敏后 120 字), severity, blocking}`，报告里不回显原文凭证。

### 1.5 数据模型与接口

```sql
-- 一次扫描 = 一个版本的一个结果；同 artifact_sha256 + rules_version + sbom_hash 可复用
CREATE TABLE plugin_scan (
  id            UUID PRIMARY KEY,
  plugin_id     UUID NOT NULL,
  version       TEXT NOT NULL,
  artifact_sha256 TEXT NOT NULL,
  sbom_hash     TEXT,
  rules_version TEXT NOT NULL,
  status        TEXT NOT NULL,          -- passed | blocked | unscanned | error
  max_severity  TEXT,
  findings      JSONB NOT NULL DEFAULT '[]',
  summary       JSONB NOT NULL DEFAULT '{}',  -- {deps:12, high:0, blocked_reason:...}
  scanned_by    UUID,
  scanned_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 误报豁免：必须带原因和过期时间，过期自动失效
CREATE TABLE plugin_scan_allow (
  id         UUID PRIMARY KEY,
  plugin_id  UUID NOT NULL,
  rule_or_cve TEXT NOT NULL,   -- 规则 id 或 CVE 编号
  reason     TEXT NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL,
  created_by UUID NOT NULL
);

CREATE TABLE scan_rule_set (
  version     TEXT PRIMARY KEY,
  sha256      TEXT NOT NULL,
  uploaded_by UUID,
  uploaded_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  active      BOOLEAN NOT NULL DEFAULT false
);
```

接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/spaces/{id}/plugins/{slug}/publish` | 扫描后发布；被阻断返回 **409 + 完整报告** |
| GET | `/spaces/{id}/plugins/{slug}/scan` | 指定版本的扫描报告 |
| POST | `/admin/scan/rescan` | 按 slug/version 或全量重扫（依赖库或规则更新后） |
| GET / PUT | `/admin/scan/rules` | 读取/上传规则集，上传即热加载 |
| POST | `/admin/scan/rules/reload` | 立即重载 |
| GET / PUT / DELETE | `/admin/scan/allow` | 豁免管理 |

**发布流程插入点**（`internal/plugin.Manager.Publish`）：在 `Derive` 之后、`UpsertPlugin` 之前执行扫描；阻断则直接返回，草稿与候选状态不变，不产生任何发布副作用。

**扫描的定位是元数据，不是快照的一部分**：报告独立存储，绝不修改发布件，`artifact_sha256` 不变。因此可以在**发布之后**因规则升级而重扫，结论可以变，产物不能变。

### 1.6 持续重扫

CVE 是发布**之后**才出现的，一次性扫描等于没扫。

- 每日一次批量重扫（可配置），按 `artifact_sha256 + rules_version` 去重；
- 新增 high 以上漏洞 → 告警 + 市场打标，**不自动禁用**（禁用是管理动作，需人决定）；
- 报告里记录 `scanned_at`，市场显示「依赖 12 · 高危 0 · 11-14 扫描」，过期显示「已过期，建议重扫」。

## 2. 运行时隔离

### 2.1 分档原则

| 场景 | 沙箱模式 | 网络 | 写权限 |
|---|---|---|---|
| 空间草稿（随时在改） | `read-only` | 无 | 仅私有 tmp |
| 已发布 / 已安装 | `workspace-write`（当前插件子目录） | 无 | 当前插件目录 + tmp |
| 需要出网的插件 | 同上 | 仅 proxy socket | 同上 |
| `shell_exec`（不需要网） | `workspace-write` | 无（`--unshare-net`） | 空间工作区 + tmp |
| `shell_exec`（需要网，审批通过后） | `workspace-write` | share-net，私网由 NetworkPolicy + 容器内 iptables 封禁 | **只有空间下的 `.deps`**，工作区被 tmpfs 遮蔽 |

**私网封禁分两层，缺一不可**：

- **NetworkPolicy**（`deploy/local/15-runner-netpol.yaml`）：集群层，生产环境的标准做法。
- **容器内 iptables**（`deploy/runner/entrypoint.sh`）：不依赖 CNI。OrbStack / k3d 默认没有 CNI，NetworkPolicy 会被 API Server 接受、但不执行——实测沙箱能直接访问同集群 Pod。执行体容器带 `NET_ADMIN`，启动时加规则；没有该能力时降级为只靠 NetworkPolicy，并在日志里告警。

规则只拒**主动发起**的 TCP（`--syn`，即带 SYN 不带 ACK）。按目标网段整段 `REJECT` 会把 kubelet 探针的 SYN-ACK 一起打掉，表现是 Pod 一直 `Running` 但探针超时、被反复重启——这个坑踩过一次。DNS（53）单独放行，否则域名全部解析失败而 IP 直连正常，很难归因。

### 2.2 文件系统：从"全盘只读"改成白名单（已实现）

原来 `--ro-bind / /` 让插件能读 `{STORAGE_ROOT}` 下所有空间的文件和凭证目录，这是私有化部署里最现实的风险（同机数据密度高）。现在是白名单：**没列出的路径在沙箱里根本不存在**。

| 挂载 | 来源 | 权限 |
|---|---|---|
| 系统基线：`/usr`、`/bin`、`/sbin`、`/lib*`、`/etc/{ld.so.cache,ld.so.conf*,passwd,group,nsswitch.conf,hosts,localtime,timezone,ssl,pki,alternatives}` | 宿主 | ro |
| 解释器目录（`Cmd[0]` 解析结果） | 宿主 | ro |
| `SANDBOX_READ_EXTRA` | 宿主 | ro |
| `Spec.FS.Read`（插件层传入：空间工作区 / 清单 `fs.read`） | 空间 | ro |
| `Spec.Dir` | 空间 | ro |
| `Spec.FS.Write` + `Spec.Dir`（仅 workspace-write） | 空间 | rw |
| 私有 tmp（`TMPDIR` + `HOME`） | `MkdirTemp` | rw |

macOS 侧同样收敛（`seatbelt.go`），并且比别人多两条必需项，都是实测踩出来的：

```scheme
(allow file-read-metadata (literal "/") (literal "/Users") ...)  ; 解释器 realpath 要 stat 每一级父目录
(allow file-read* (literal "/") (subpath "/usr") ...)           ; 根节点本身 subpath 覆盖不到，缺了直接 abort
(allow file-write* (subpath "<workspace>") (subpath "<tmp>"))
```

漏掉任何一条的表现都是「进程没有任何输出直接退出（exit 134 / -1）」，与权限毫无关联，极难排查。

**运行时装在非标准位置**（npm 装的 deno 是 `#!/usr/bin/env node` 包装脚本、自建 node/python）必须配 `SANDBOX_READ_EXTRA` 把安装前缀挂进去，否则会得到 `Cannot find module` 这类与沙箱无关的报错。

macOS Seatbelt 的 `process-exec*` / `signal` / `mach-lookup` 仍未收敛，见 §2.6。

### 2.3 网络：全局代理 + 无网默认

**v1 实现形态（已定）**：`--unshare-net` 保留，把宿主代理的 unix socket bind 进沙箱，作为**整台沙箱唯一的出网通道**——这就是本文所说的「全局网络代理」：不是透明劫持，而是「除代理外无路可走」。代理在宿主侧做域名白名单、IP 校验与审计，插件侧只多一个 `WA_EGRESS_PROXY` 环境变量和一个 socket 路径。

透明劫持（netns 内 `REDIRECT` + SNI 嗅探）列为 P2 预案，只在出现「改不动又必须出网」的插件时启用，且仅 Linux。

**默认 `--unshare-net`，插件完全没有网络。**

需要出网时只有一条通道：宿主代理的 unix socket。

| 通道 | 适用 | 机制 |
|---|---|---|
| **`wa.fetch`（唯一）** | 全部出网（REST API、webhook） | 插件发 absolute-form 明文 HTTP/1.1 → 宿主代理做 TLS + 白名单 |
| **凭证** | 需要鉴权的请求 | `host.secret(名称)` 取明文，插件自己拼 header |

早先的判断是「给 Deno 插件套代理不生效，一律走 `host.call`」。这个判断在 HTTP 代理 + absolute-form 这条路上不成立：插件侧不需要自己建 TLS、也不需要把请求塞进自定义连接，只要往 socket 写一段 HTTP/1.1 即可。代价是**只支持 HTTP/1.1 请求-响应**。

```text
插件(沙箱内) --unix socket--> 宿主 HTTP 代理 --域名/动词白名单--> 目标
                                ├─ absolute-form 解析：目标域名由插件给出，白名单在宿主判定
                                ├─ 代理解析 DNS 并校验全部 IP（私网 / 回环 / 169.254 拒绝）
                                ├─ TLS 由代理建立（min TLS1.2）
                                ├─ 不跟随 30x：白名单只对第一跳成立
                                └─ 审计：哪个空间、哪个插件、哪个域名、放行或拒绝、字节数
```

对应配置：

- 沙箱：`--unshare-net` 保留，代理 socket 通过 bind（Linux）/ 单文件放行（macOS）挂进去，这是 netns 里唯一的对外通道；
- Deno 权限：`--allow-read` / `--allow-write` 都要带 socket 路径，外加 `--allow-net`——unix socket 的检查是这三件套，少一个是 `NotCapable`；
- 代理侧拒绝直接返回 403 并带原因，不静默超时。

### 2.3.1 依赖的网络访问（与上表不是一回事）

`wa.fetch` 只覆盖**插件自己写的代码**。npm 依赖内部调 `fetch` / `node:http` 时不会经过 `wa.fetch`，也不会自动走 socket 代理——它只会直接 `connect()`，在没有 netns 路由的沙箱里失败。

并且 Deno 的权限是**进程级**的：`--allow-net` 一旦授予，插件代码与依赖代码同时获得该能力，无法按模块区分。所以依赖要出网只有两条路：

| 做法 | 覆盖范围 | 代价 |
|---|---|---|
| **1. 让依赖不联网**（默认） | 全部 | 纯计算的依赖（解析、格式化、加解密）够用；自带网络的 SDK 不能用 |
| **2. 注入适配器** | 支持自定义 `fetch` / `httpClient` 的依赖 | 插件层包一个 fetch，内部转 `wa.fetch` |
| **3. 透明代理**（P2） | 未修改的依赖 | netns 内 `REDIRECT` + SNI 嗅探；只能判 TLS 域名，QUIC / ECH 失效，复杂度高 |

另有一条「便宜但弱」的选项：直接 `--allow-net=host:port`。可用，但失去动词控制、响应上限、私网拒绝与审计，DNS rebinding 也拦不住，不作为默认。

**因此 socket 代理的定位是「插件自己代码的默认出网通道」，不是「给任意依赖兜底」。**

### 2.3.2 已实现（v1）

| 组件 | 位置 | 状态 |
|---|---|---|
| 宿主侧代理（unix socket、域名白名单、私网拒绝、审计事件） | `internal/egress`（HTTP 代理 + SOCKS5） | 已实现，含单测 |
| 沙箱挂载代理并保持 `--unshare-net` | `sandbox.Spec.Proxy`（bwrap `--bind` / Seatbelt `allow network-outbound` + 文件读写放行） | 已实现 |
| 约定环境变量 `WA_EGRESS_PROXY` | `sandbox.buildEnv` | 已实现 |
| 每插件独立代理 + deno 权限 | `internal/plugin/egress_pool.go` / `runtime_tool.go` | 已实现，含端到端验证（沙箱内 `wa.fetch` 取到 200，白名单外 403） |

接线约束（已按这三条落地）：

1. **按插件**建代理，不全局共享——`egress.Policy` 是单一接口，共享 socket 无法区分调用者，只能合并白名单；
2. 白名单只从清单 `capabilities.hosts` 推导（`Manifest.NetHosts()`），与 `search.Guard` 同源；没声明就没有 socket；
3. 开启即受审计：每次连接记 `host / 端口 / 放行与否 / 字节数 / 耗时`。

Deno 侧需要三个权限：`--allow-read`（含 socket 路径）、`--allow-write`（含 socket 路径）、`--allow-net`。少一个都是 `NotCapable`。

### 2.4 其它加固（私有化最小集）

| 项 | 做法 | 优先级 |
|---|---|---|
| 嵌套 user namespace | `--disable-userns`（bwrap 0.9+），配合 `--assert-userns-disabled` | P0 |
| capability | `--cap-drop ALL` | P0 |
| 进程数 / 内存 | cgroup v2 `pids.max` / `memory.max` | P1 |
| tmp 写满 | tmpfs 或外部配额 | P2 |
| 只读根 | 白名单挂载后天然满足 | P0 |
| 审计 | 记录 `sandbox backend / mode / network / proxy 决策` | P0 |

不做：微虚拟机、seccomp 白名单（可选 denylist）、侧信道、Landlock（与挂载白名单重复）。

### 2.5 两种运行模式：一次性与常驻

平台只有两种沙箱运行形态，都由 `sandbox.Runner` 承载，区别只在生命周期：

| 模式 | 入口 | 用于 | 生命周期 |
|---|---|---|---|
| 一次性 | `Runner.Run(ctx, Spec)` | 大模型单次指令（`shell_exec`）、试运行（`plugin_try`）、搜索脚本 `plan/map` | 一次调用一个进程，结束即回收 |
| 常驻 | `Runner.Start(ctx, Spec)` + `Manager` 进程池 | 声明了 `runtime.resident` 的 `kind=tool` | 每个插件一个子进程，复用直到空闲/失效/崩溃 |

**插件默认一次性**：清单不写 `runtime.resident` 就每次起新进程、跑完即退，不占常驻池。
声明 `runtime.resident: true` 后才进入常驻池（`docs/插件体系设计.md` 的执行器形态随之调整）：

- 键是 `空间|slug|目录`：换版本、换目录、草稿变更都是另一个进程，不复用旧代码；
- 同一进程内 **invoke 串行**，与插件侧 SDK 的队列语义一致，常驻不改变可见行为；
- 空转 10 分钟回收（`PLUGIN_PROC_IDLE_SECONDS`），总数上限 32（`PLUGIN_PROC_MAX`）；
- 安装 / 升级 / 停用 / 卸载 / 空间重载 / 撤销草稿变更都会立刻 `closePrefix` 杀掉进程——**停用是 kill switch，不等空闲回收**；
- 崩溃或超时即杀进程并从池里摘掉，下一次调用重新起，绝不会复用「协议停在半截」的进程；
- `Spec.Resident=true` 表示**不施加墙钟**，否则 30 秒后进程会被 ctx 连带杀掉，常驻就退化成一次一进程。

试运行固定走一次性（`OneShot`）：草稿代码不能挂在池里，否则改一次就要等空闲回收；即使清单声明了 `resident` 也一样。

### 2.6 文件权限：默认只读，写必须声明子目录

| 层 | 规则 |
|---|---|
| 平台默认 | 只能**读**自己所在空间的工作区（`spaces/<id>/files`），**不能写**；空间之外一律不可见（含 `published/`、其它空间、`secrets/`） |
| 插件目录 | 总是可读：已发布但不可扩展的插件运行目录在 `published/` 下，不在空间工作区里 |
| 清单 `fs.read` | 声明后就只读这些**子目录**（默认是整个空间工作区）；越出（绝对路径、`..`、`.`）发布即失败 |
| 清单 `fs.write` | **写权限的唯一来源**：不声明就完全不能写；只写声明的子目录 |
| 清单 `fs.read_only` | 整插件只读：即使声明了 `fs.write` 也不给写 |

```json
{
  "fs": {
    "read":  ["data/", "docs/"],
    "write": ["output/"]
  }
}
```

两条硬规则：

- **写默认关闭**：读默认放开是为了让老插件不失效，写是唯一产生持久副作用的操作，默认给整个空间可写等于把发布审核当摆设。
- **只能声明子目录**：`.`、`/`、`..` 一律拒绝——「声明整个空间」不在选项里，要读全部就别写 `fs.read`。

`fs` 是文件权限的唯一入口：`capabilities` 里写 `fs.read` / `fs.list` / `fs.write` 会**解析失败**（这三个已经不是宿主 method，留着只会让人误以为还能用），`Derive` 在声明了 `fs.write` 时把风险抬到 L3。因为只能收紧、不能扩权，这个字段不需要单独审批。

安装与升级确认里会展示权限清单（见 §2.7）：文件读范围、写范围、出网域名、凭证引用都来自同一份清单。

**文件不再经过宿主**：`host.call("fs.*")` 已废弃（调用直接报错），脚本用 `Deno.readTextFile(wa.path("data/x"))` 直接读。同一份 `sandbox.FS` 现在有两个执行点——`bwrap`/`seatbelt` 挂载决定「路径在沙箱里存不存在」，`--allow-read` / `--allow-write` 决定「deno 允不允许读」。只给挂载不给权限，脚本会拿到 `NotCapable`；只给权限不给挂载，路径直接 `ENOENT`。两者都从 `fs` 段推导，缺一层就等于没管。

### 2.7 权限展示：安装前必须看得见

权限不能只写在清单里。安装/升级前把「它会拿到什么」摆给用户，是唯一能让权限模型真正起作用的环节——用户看不见的权限等于没有约束。

- 文案由 `Manifest.Permissions()` 单点生成：文件读/写范围、出网域名与动词、凭证引用、shell、远端工具白名单。前端只渲染，不自己拼句子（否则同一个插件在两个页面会有两种说法）。
- 市场目录返回 `permissions`，空间列表返回已装版本的 `permissions` 与待升级版本的 `latest_permissions`。
- 安装与**升级**都弹确认：升级不动权限那套逻辑就会变成静默提权（新版本加个 `fs.write` 就生效了）。
- 权限里不出现完整 URL：只给主机名，避免把带 token 的查询串带进界面。

### 2.8 出网：代理是唯一通道

| 通道 | 用途 | 谁做 TLS | 白名单 | 可见范围 |
|---|---|---|---|---|
| `wa.fetch` → unix socket 代理 | 普通 HTTP 出网 | 宿主代理 | `capabilities.hosts` + `verbs` | 域名、路径、方法、内容 |
| `new WebSocket` + `HTTPS_PROXY` | `wss://` 长连接 | 宿主代理建 TLS，之后是端到端加密 | `ws.connect.hosts` | 只到握手：域名与路径 |
| `host.secret(名称)` | 取凭证明文 | — | 清单里逐条声明的 `secret.use.name` | 不涉及 |

插件进程仍然 `--unshare-net`，唯一出口是挂进沙箱的 `/tmp/wa-egress-<hash>.sock`。

- **每个插件实例一条代理**：`egress.Policy` 是单一接口，共享 socket 无法区分调用者，只能把所有插件的域名并成一张大名单——那等于白名单失效。
- **TLS 必须在宿主**：Deno 的 `startTls` 只接受 `TcpConn`（`UnixConn` 直接 `BadResource`），`createHttpClient` 的 `createConnection` 也已被移除。所以插件发 absolute-form 明文 HTTP/1.1，代理侧建 TLS。
- **宿主不再代发请求**：`http.request` 从宿主 ABI 里删掉了，它现在只是清单里的出网声明（决定代理白名单与动词）。凭证改由 `host.secret(名称)` 下发，插件自己拼 header。
- **凭证按名授权**：`secret.use` 必须写 `name`，一条能力一个凭证；没声明过的名字 `secret.get` 直接拒绝。否则「有 secret.use」就等于能读整个 `plugin` scope，一个通用插件可以把平台上所有插件的密钥取走。
- **代价要写进风险**：明文进入插件进程，插件代码可以把密钥打日志或带出去，所以「`secret.use` + 外部写」判 L4，安装确认里也必须显示这句话。
- **不跟随跳转**：白名单只对第一跳成立，跟随等于让目标决定去哪。
- **WebSocket 走独立能力**：不并入 `http.request`，因为 101 之后宿主什么都看不到——它既不是「读」也不是「写 HTTP」，而是「一条通向某域名的加密管道」，风险按 L3 计，安装确认里单独列一行「建立加密隧道」。
  - 实现靠 Deno 自己的代理支持：注入 `HTTPS_PROXY=unix:<sock>`（Deno 2.9 认这种写法，说明它不是标准 HTTP 代理语义，而是「本地管道」）。
  - 代理收到的是 absolute-form 的 `GET https://host/path` + `Upgrade: websocket`，不是 CONNECT；代理自己连上游、转发握手、收到 101 后 Hijack 并双向透传。
  - 主要面向 `wss://`；`ws://` 明文也能走，但那条线上宿主看得见内容，权限文案不区分（都算「建立隧道」）。
  - 局限：HTTP/2、gRPC 流仍然不支持。

审计记录在连接级别：host、port、成败、字节数、耗时。

### 2.9 执行器接口（`sandbox.Spec`）

```go
type Spec struct {
    // ... 现有字段
    Proxy    string // 出网代理 unix socket；空 = 完全断网；与 Network 互斥
    FS       FS     // 文件白名单：Read / Write，绝对路径
    Resident bool   // 长驻进程：不施加墙钟
}
```

`ModeReadOnly` 下 `FS.Write` 一律被忽略——「只读档位」是调用方意图，不能被一个字段悄悄推翻。

## 4. 已知风险（记录，暂不防护）

### 4.1 DNS 相关风险

**结论：不做 DNS 层防护。** 不是低估风险，而是这个层面的防护在本场景里收益接近零，且真正有效的措施在别处。

| 风险 | 是否防护 | 理由 | 实际替代措施 |
|---|---|---|---|
| DNS 缓存投毒 / 污染 | 不做 | 私有化内网 DNS 由客户 IT 把控，平台无法也不应介入；HTTPS 下污染表现为**连不上**而非被窃听 | 证书校验不可关闭；关键出口可选 SPKI 固定 |
| DNS rebinding | 不做 DNS 侧防护 | 攻击者拥有域名与权威 NS，记录是**合法签名**的，DNSSEC 一路通过，无法在解析层识别 | **拨号期校验 IP**（`Guard` 已有）：一次解析、校验全部 A/AAAA、直连校验过的 IP |
| 多 A 记录轮询 / TTL=0 二次解析 | 同上 | 属于 rebinding 的变体 | 同上：校验所有记录 + 校验与连接同源 |
| 内网 DNS 被篡改 | 不做 | 能改内网 DNS 的等于客户 IT（已有 root），不是沙箱能防的对手 | 审计记录解析结果，事后可追溯 |

**明确不做**：DNSSEC 验证、内置 DoH、多 DNS 投票。

**三条替代性质**（比“DNS 安全”可验证，且必须满足）：

1. **Fail-closed**：解析或校验失败即请求失败，不降级、不重试到其它地址；
2. **凭据局部性**：每个密钥只对一组域名有效，且不进 URL / query；
3. **位置收敛**：出网只有一条路，且那条路上没有内网路由。

满足这三条后，DNS 结果被污染或来回变化都不会造成凭据泄露或内网可达，无需额外防护。

阶段：**记录，不实现**。若未来出现“必须按域名精细控制、且插件使用未修改的第三方 HTTP 客户端”的需求，再评估 §2.3 的透明代理方案（Linux only）。
