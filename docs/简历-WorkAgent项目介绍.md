## 1. 简历精简版（可直接粘，6 行）

**WorkAgent — 企业级 Agent 平台（Go / React / Deno / K8s）**｜Agent 运行时负责人

- 自研 LLM Harness：可替换编排契约（`Capabilities` 八项能力声明 + `AGENT_IMPL` 切换），预算、审批挂起、checkpoint、上下文压缩全部平台侧实现，框架类型不出模块边界。
- 上下文工程两层：跨轮「摘要 + 向量召回 + 16 条滑窗」（24000 字预算），轮内「丢过程留结论」的确定性折叠（输入达窗口 60% 触发，不调模型、零失败成本）；同一阈值触发「把剩余读取与筛选拆给子 Agent」的强制提醒，主上下文只留结论。单轮默认 40 轮 / 150 次工具，累计 token 默认不限（长任务不按写死的成本阈值砍断）。
- 长任务可靠性：按「工具 + 规范化参数」指纹去重（同参数 + 同结果下一次即拦截，结果在变的轮询放行）、连续 2 轮无新信息即收回工具要求作答（只收工具不终止循环）；工具参数上限跟随 `LLM_MAX_TOKENS`，被截断的半截 JSON 一律不执行。
- 暂停与恢复：审批即暂停（run 落 `waiting_approval` 终态、断点保留未执行调用），决策落 `approval` 表按 `run_id + args_hash` 复用，批准后从断点续跑、已执行调用按指纹回放不重跑；流式帧落 Redis 支持 `after_offset` 断流续传。
- 权限与审批：授权只有「插件安装 / 启用」一条路径；审批只看动作类别（出网非只读、MCP 声明写、命令名单、安装方档位），风险等级只做展示；shell 联网由模型声明 `need_network` 决定，与命令名单合成一张卡、一次点击覆盖两件事。
- 执行面：K8s 每空间一个空间容器 + 每租户一个插件容器，容器内一次调用一个 bwrap；出网走每插件实例独立 unix-socket 代理 + 清单白名单；常驻进程池崩溃退避重启 + 熔断；插件发布扫描（OSV CVE + 提示词注入 + 凭证）规则热更新。

## 2. 简历完整版（项目经历展开）

### 2.1 项目背景

企业内网的 Agent 平台。目标不是「能聊」，而是 Agent 能接进真实业务：以用户身份执行、工具按插件安装授权、高危动作审批、执行在容器沙箱内、失败可恢复。

技术难点集中在 Harness——如何让模型在长任务里不跑偏、不失忆、不烧穿预算，以及「人点同意」这件事怎么在分布式进程里不丢；另一半在边界——权限如何没有中间态、用户代码如何不碰到平台。

团队的取舍是：**流程从对话和文件里长出来，而不是先画图**。技能、工具、MCP、UI 组件、智能体统一为插件，走同一条「开发 → 发布 → 安装 → 运行 → 卸载」链路。

### 2.2 我负责的部分

#### 1）Harness 分层与可替换编排

- 定义 `agent.Agent` 契约，用 `Capabilities` 声明实现能力（tools / parallel_tools / streaming / reasoning / approval / resume / dispatch / guard），上层按能力降级并向客户端说明，而不是假设所有实现都一样。
- 实现注册制：各实现 `init()` 注册，装配层按 `AGENT_IMPL` 选择；内置 ReAct 循环（默认）与无工具单轮直答，Eino 适配预留为唯一允许 import 框架的子包。
- 关键约束：**框架类型不出模块边界**。Run 状态机、预算、审批挂起、checkpoint、上下文压缩全部平台自研（`internal/session` / `internal/tool` / `internal/ctxmgr` / `internal/policy`），换编排框架不动业务层。
- 预算是多维的而不是单看轮次：轮次 40、工具次数 150、并行 4、累计 token 默认不限（成本敏感部署可显式设上限）、总墙钟 2h、无事件 10m 即中断；超预算按 `cancelled` 收尾并保留已生成内容，不伪装成失败。

#### 2）上下文工程（Context Engineering）

- **跨轮三段式组装**：更早消息压成事实性摘要（600 字，缓存到 `session_summary`）+ 按需向量召回（cosine 阈值 0.35、TopK 4）+ 最近 16 条原文滑窗，总量按 24000 字预算从新到旧装配，不按条数或字节硬截。
- **轮内压缩**：一轮长任务里 messages 会随工具回执线性膨胀且每轮重发，撞窗口不是降级而是整轮报错。做法是「丢过程、留结论」——从上一轮真实 `input_tokens` 达到窗口 60% 起，把较早的工具往返折成一条进展记录，保留系统提示词、最近 3 轮原始回执、每轮已对用户说过的正文；真撞 context-length 时折到只留 1 轮，且只在「一个增量都没吐」时重试，避免用户看到答案重复。
- **关键取舍**：压缩不调模型。判决与摘要是确定性的字符串处理，零失败、零额外成本，否则压缩自身成了新的故障点；跨轮摘要的成本则摊在「反正要发一次请求」上。
- 修过的一类静默 bug：单条消息自己就超预算时，旧实现从新到旧装不下会 `break`，导致上下文里一条都没有、用户说的话模型一个字没听到且不报错——改为截断保留头部。

#### 3）工具调用可靠性（长任务不跑偏）

- 进度守卫每轮回答三个问题：这一步有没有带来新信息、下一步还有没有价值、该不该强制收尾。判断全部基于调用指纹与结果摘要，**不额外花一次模型调用**。
- 同工具 + 相同参数（JSON 规范化后取指纹，键序、空白不影响）**结果与上次完全相同时下一次即直接拦截**并回填固定标记；报错 / 空回执没有结果可比，按次数兜底到第 3 次；结果在变的同参数轮询放行（等日志、等构建是有效观察）。连续 2 轮无新信息（空结果 / 报错 / 与之前完全相同）则收回工具、要求用现有信息作答。
- 只「收回工具」不「终止循环」：终止的代价必然是用户收到一条空回答，强制收尾还有机会拿到结论；拿不到才返回 `ErrBudgetExceeded` / `ErrStalled`，两者在语义上分开（预算用尽 vs 再做也一样）。
- **参数上限与输出上限是同一个约束**：单次调用参数上限由 `LLM_MAX_TOKENS` 推导（下限 16KB）而不是写死；`finish_reason=length` 时参数不完整，这类调用**一律不执行**，并回填「切几块、第一块用什么 mode、后续怎么续」的可执行说明，避免模型原样重发再撞同一个上限。
- 支持同轮多工具并行（上限 4）、reasoning 过程透传、SSE 流式增量；按「思考 / 正文 / 工具」记录 Timeline 段序，落库后回看顺序与发生时一致。

#### 4）暂停与断点续跑（分布式下「等人」不能丢）

- **审批即暂停**：命中确认就登记待办、推 `approval.req`，本轮直接收尾（run 落 `waiting_approval`），断点里留着那条没执行的调用；用户点同意由决策驱动从断点续跑，点拒绝则把「用户拒绝」当回执交给模型。全程不占着执行体等人，也没有「超时替用户做决定」。
- **暂停那一轮照样落一条消息**：未执行的调用以「待审批」状态写进 `message.parts`，续跑接着同一条消息写（正文另起段、parts 续在后面、用量相加，旧卡按 call id 顶掉；模型重发导致 id 变化时退回「工具名 + 参数」且两边过同一个 8KB 截断函数），一轮始终只有一条回答。
- **Checkpoint 三条硬约束**：批次发出 `tool_calls` 时先写快照（带 `pending`），每拿到一条回执再写一次；续跑先把 `pending` 补齐再问模型；已完成的调用靠 `tool_call.result` + 参数指纹回放入 `Replay`，副作用不重来。
- 等待期每 15s 续心跳（等人不是卡住），进程没了留两道心跳余量后被清扫收掉，审批行留到过期；待办与断点同寿命 7 天，`PurgeStaleResumes` 定期清理——老断点接上去，模型面对的是一份早就过期的世界。
- **流式可续传**：增量帧与正文快照每 1s 写 Redis（`wa:run:*`，帧上限 8192），客户端用最后一帧 offset 作为 `after_offset` 重连，刷新不丢当前轮；未配置 Redis 时退回进程内存，单实例可用。

#### 5）多 Agent 协作与任务体系

- 子 Agent 是**工具**（`agent_dispatch`）而不是编排图：主 Agent 决定何时整件事交出去，子 Agent 复用同一套工具链、策略与审计，但上下文与轮次预算隔离。
- 约束参数化：子任务默认 3 轮（且不超过父剩余轮次）、结论回填上限 4KB（必须自包含，不搬过程）、派发深度默认 2 层、工具集合只能是父集合的子集；子 Agent 有独立追加提示词（直接做、不扩范围、缺信息说明缺什么），权限仍在叶子调用上判定。
- **轮内任务清单**（`plan_write` / `plan_read`）：整份覆盖而不是增量更新（结果只取决于最后一次调用）、上限 30 条、状态闭包在单次 Run 里（Agent 是共享单例，挂结构体上会串会话），清单版本变化才推 `plan.updated`。
- **跨人派发**（`task_create` / `task_list` / `task_remind` / `task_cancel` / `task_reply`）：把事交给同事时，平台在其**个人空间**代建子会话（他可能无权进入当前空间，派发不该顺带开权限），不写任何 `space_member`；任务说明分段（需求 / 已做 / 待确认 / 确认后），同人同标题未结束即拦截并引向催办；回执由子会话侧显式 `task_reply` 产生，写回父会话后自动续跑一轮，但父会话已有活跃 run 时只落消息不打断，且自动 run 受「每会话每分钟 3 次」限流，十个回执不会催出十轮模型调用。

#### 6）多模型路由与成本

- `Route = Primary + Fallbacks + Model 覆盖 + Required 能力标签`，三条路由 `chat` / `summary` / `embedding`；摘要、标题与轻量任务走小模型。
- 降级有硬约束：只有协议族一致（schema 兼容）才降级，否则报错而非静默降质；流式已向前端输出内容后不再降级，避免重复文本。
- OpenAI / Anthropic 双实现，Provider 抽象 + Router 统一流式回调与用量统计。

#### 7）权限与审批（Agent 落地最关键的一块）

- **授权只有一条路径**：插件安装 / 启用即授权。工具能出现在空间的工具列表里，就说明所属插件已装好，这个动作本身就是授权；数据库里已经没有 Resource / Grant / ToolBinding 这些中间层（对应迁移已 drop）。
- **审批按动作类别判定**，只有四类会停下来：出网非只读（清单 `verbs` 含 GET/HEAD 之外的动词）、MCP 显式声明 `tools.writes`、shell 命中「需确认命令」名单（默认 `rm` / `dd` / `chmod` / `sudo` / `mount` 等，`$(...)`、反引号、`xargs`、`sh -c`、`find -delete`、`git reset --hard` 等组合形态一并命中）、安装方把该插件档位设成 `always`。
- **风险等级只用于展示**：卡片头常驻文案徽标（只读 / 查询 / 写入 / 高危，不显示 L1–L4 编号），事件与历史消息都带 `risk` / `risk_label`，因此不审批的调用也能看出这一步动了什么。
- **判定依据**：等级 × 副作用需要人做二维推理，实际效果是用户对每一次写都点同意，审批退化为形式；而空间内写的范围被工具锁死在当前工作区（工具不接受 `space_id`），删错还有回收站与审计。审批只留给「不可逆且平台无法替代用户判断」的动作。
- **shell 的联网准入**：给不给网由模型用 `need_network` 声明，再由命令内容决定——只装依赖（`pip install` / `npm i` / `apt install`）不看声明直接有网、不审批；声明要网且命令里有脚本或网络工具（`curl` / `wget` / `ssh` / `nc` 等）时先确认，批准后有网执行、拒绝即整条不执行；没声明就按无网执行，脚本 / 网络工具失败且错误像网络问题时申请一次「联网重跑」。判据只在 `internal/tool/shellnet.go` 一处，执行、审批、升级重跑都读它，避免「批了没网 / 没批却联网」。
- **一张卡覆盖两件事**：一条命令同时命中命令名单与联网准入时合并成一次确认，`policy.Action.Covers` 记下每个动作键，执行侧用 `CoversKey` 判断「这次批的包含给网」——不让人对同一件事点两次、中间各续跑一轮。命令匹配只看会被 shell 解释的部分：heredoc 正文与单引号字面量里的反引号 / `$( )` 是数据（模型整篇写代码时不该每写一次就弹一次），双引号里的照常命中。
- **安装方可配档位**：`declared`（按上面判据，默认）/ `always`（每次都确认）/ `off`（都不确认），非法值一律退回 `declared`；内置工具同样吃这一档（在系统空间改，对全部空间生效）。
- **审批是持久化事实，不是内存状态**：`approval` 表一行一次调用，`pending → approved / denied / expired`，`scope` 只有 `once` / `turn`（`turn` 只对当前一次 run 有效，下一轮重新确认），`args_hash` 认「同一次调用」；刷新按 `session_id` 补回卡片。决策落库后分流：执行体还活着（决策与收尾撞车）就等它收尾时回查，避免起两份执行；否则直接在收到点击的那台实例上从断点续跑——多副本下库是唯一真相，不依赖「当初等在哪台机器」。run 结束统一 `ExpireRunApprovals`，用户下一句发话即作废旧待办与对应断点。没有审批通道时默认拒绝。
- **MCP 的「是否写」只能靠声明**：远端 server 对平台是黑盒，只有 `input_schema`，看不到实际请求，从动词推导不成立，因此由作者声明 `tools.writes`（声明后风险抬到 L3），未声明按只读处理；同时用 `tools.allow` 白名单，不默认信任远端暴露的全部工具。

#### 8）插件体系与执行面（支撑能力）

- 六类 `kind`（skill / tool / mcp / component / agent / source）共用一份 `plugin.json` 与同一条生命周期，差异只在执行器；风险与副作用由 `Derive(manifest)` 从 `capabilities` 推导，清单里写 `risk` 直接解析失败。
- 发布权与安装权分离：空间管理员只能启用本地草稿（市场出现「待发布」），**系统管理员**才能发布不可变快照；安装由空间管理员执行、只在本空间生效；`secret.use` + 外部写抬到 L4，发布与安装都需要系统管理员。
- **停用必须是真停用**：`plugin_install.status=disabled` 要在四条读路径上都生效（加载快照、检索合并、Go 内置工具注册、搜索注册表），否则开关只是个标签。
- **执行面由 `WA_ROLE` 决定，不按机器探测**：`server`（默认，含本机调试与 CI）只能创建 K8s 执行体，`SANDBOX_BACKEND` 只有 `k8s` 一档，执行体上报的后端不是真隔离就启动失败；`client`（本地 runtime）只能在本进程起 bwrap。没有「本机裸跑」「sandbox-exec」「连远端固定执行体」这些降级档。
- 执行体拓扑：**每空间一个空间容器**（跑 shell，空闲 15 分钟销毁、下次调用重建，`apt install` 只进自己的可写层）、**每租户一个插件容器**（跑插件运行与插件开发会话，常驻）；容器内一次调用一个 bwrap 沙箱，挂载表与 Deno 权限双重收口，`--unshare-net` 默认断网。
- **出网只走代理**：每个插件实例一条独立 unix-socket HTTP 代理（白名单按清单算，共享 socket 会让 A 连上 B 声明的域名），支持 WS 升级隧道与 CONNECT 兜底；宿主看不到帧、只做域名与路径级白名单。搜索源另有一条 `Guard` 通道：只允许 https、域名边界匹配、dial 阶段拒绝私网 / 回环、不跟随 30x。
- **常驻进程不按空闲回收**：声明 `runtime.resident` 才按「空间|slug|目录」复用（池上限 32），启用即启动、崩溃指数退避重启（300ms → 5s）、连续 5 次失败熔断，重装 / 改配置 / 改草稿清掉熔断；一次性进程跑完即退。
- 凭证信封加密（KEK 包裹每条凭证独立 DEK，AES-256-GCM），对外只暴露 8 位指纹，模型上下文与审计日志不含明文；工具结果回填前按规则脱敏（手机号 / 身份证 / 邮箱 / 卡号 / token）。MCP 侧按调用现签 5 分钟用户 JWT（服务令牌 1 小时），密钥只存在凭证存储与内存。
- 发布安全扫描：依赖 CVE 走 OSV batch、提示词注入与凭证泄漏走规则引擎，规则文件支持热加载（`Watch`），命中 CVE 直接阻断发布。

### 3.1 Agent 技术维度

| 业界常见做法 | 本项目的做法 | 为什么更好 |
|---|---|---|

## 4. 面试深挖：问题 → 做法 → 收益

### 4.1 「模型 40 轮还在原地打转，最后用户收到空回答」

- **现象**：轮次上限调到 40 后，失败的主因不是轮次不够，而是循环在做无用功——同工具同参数反复调、每轮拿空结果、写完文件又读回来确认。
- **做法**：调用指纹 + gain / stalled / ForceFinal 三问；只收回工具，不终止循环。
- **收益**：长任务从「预算耗尽」变成「用现有信息给出结论」，且判断不额外消耗模型调用。

### 4.2 「一轮里工具回执把上下文顶爆」

- **现象**：每轮把整份 messages 重发给模型，长任务下线性增长，撞窗口是模型直接报错、整轮失败。
- **做法**：到上一轮真实输入 token 的 60% 就折叠成进展记录，保留系统提示 + 最近 3 轮原始回执 + 每轮已对用户说过的内容；真撞墙折到 1 轮且只在没吐字时重试。
- **收益**：压缩确定性、零模型调用，越界不再导致整轮失败，也不会出现「答案重复一遍」。

### 4.3 「审批等人，进程挂了怎么办」

- **做法**：审批落 `approval` 表，等的人挂 `waiting_approval`（可恢复状态而非卡死）并每 15s 续心跳；批准时先看执行体是否还活着（避免起两份），否则从断点续跑，该动作按 `args_hash` 复用「已批准」，已完成的工具调用靠结果回放而不重跑。
- **收益**：刷新页面能补回卡片，重启不丢结论，多副本下库是唯一真相。

### 4.4 「为什么不是每个写操作都审批」

- **判断**：审批的价值在于「不可逆 + 平台无法替用户判断」。空间内写的范围被工具自己锁死，删错有回收站和审计，不需要人看；把这类动作也弹窗，会让用户对确认框脱敏，真正危险的出网写反而被淹没。
- **做法**：判定降成一维——只看出网动词、MCP 的 `tools.writes`、命令名单、安装方档位；等级退成展示徽标，让不审批的调用也能看出动了什么。
- **收益**：确认次数集中在真正需要判断的动作上，事后 review 的信息反而更完整。

### 4.5 「shell 到底给不给网」

- **问题**：给网是外发风险，不给网是大量命令白跑；平台无法判断一条命令要干什么。
- **做法**：让模型声明 `need_network`，平台只负责「它说要网之后要不要人看一眼」——装依赖不看声明直接有网（终点由安装源决定，沙箱里没有凭证与业务数据），脚本与网络工具先确认；没声明就无网跑，失败像网络问题时申请一次联网重跑。判据收敛在一个文件，执行 / 审批 / 升级共用。
- **收益**：常见装依赖不必人工确认，跑脚本与网络工具只确认一次，真正「把数据发出去」的动作一次不落，且不会出现「批了没网」的错位。

### 4.6 「为什么服务端不直接在本机跑」

- **问题**：本机跑最省事，但节点内核、镜像与安全上下文不由我们决定；开发机探测到 bwrap 就裸跑，测出来的不是生产跑的东西。
- **做法**：`WA_ROLE` 两档互斥，服务端角色只允许 K8s 执行体、执行体自报后端不是真隔离就启动失败；容器里再用 bwrap 做一次调用级隔离，路径全部虚拟化（`/workspace`、`/pkg`、`/cache`），宿主目录不出现在任何报错里。
- **收益**：开发、CI、生产同一套执行形态；空间之间靠挂载表隔离，Pod 边界负责 `/usr` 与生命周期。

### 4.7 「Harness 改了不知道有没有改坏」

- **做法**：`evals.json` 双类用例。`kind=tool` 无需模型，发布门禁强制跑；`kind=agent` 脚本化模型回放，断言停止原因、工具序列、轮次与拦截次数，进 CI。
- **收益**：Harness 行为可回归，且发布门禁不依赖外部模型可用性。

4. 不要写「sandbox-exec / Seatbelt / 本机执行 / `SANDBOX_BACKEND=remote`」——这几条都已删除；服务端只有容器化执行体。
5. 不要写「审批 5 分钟超时按拒绝」——审批没有超时，一直不点就一直停着。
6. 不要写「常驻进程空闲回收」——常驻进程不按空闲回收，只有崩溃重启 + 熔断。
7. 不要写「异步工具轮询（`waiting_task` / `async_call`）」——方案已设计、代码未落地。
8. 不要写「本地空间（`space.type=local`）已上线」——设计定稿未实施。
