# 资源说明

资源包括：MCP、Tool、Skill、前端组件、数据库等。

## 1. 开发态（空间中的原始文件）

- 资源以文件形式存在于空间中，**允许 Agent 编辑**；用户空间不限制层级，建在哪一层就在哪一层。
- 开发态资源只在当前空间可见，其他空间不可见。
- 技能、工具、MCP 列表中同时展示开发版与发布版，开发版需明确标注。
- 同时存在开发版与发布版时：Agent 默认使用发布版；要用开发版必须由用户明确指定；检索命中同名资源时，Agent 必须先让用户选择，不得自行假设。
- 只有开发版时，Agent 可以直接使用，无需询问。

## 2. 内置资源（系统空间）

- 系统空间的内置资源**不允许 Agent 编辑**，只可读取与复制。
- `.meta.json` 标记为内置资源，前端显示标签，并禁止删除、禁止添加子目录。
- 管理员在系统空间中让 Agent 创建的资源属于普通资源，可编辑；创建时禁止占用内置资源的保留名。

## 3. 发布

- 发布时指定：版本号、发布说明、**用户范围**（`public` 全部可见 / `private` 仅自己可见）。
- **没有「必须加载 / 可选加载」**：所有资源一律由模型按需检索，不做预加载，避免挤占上下文。
- 发布后的资源进入「资源管理」板块（与「工作空间」同级），**不存放于工作空间**，使用独立的发布目录。
  - 发布件结构与开发态不同：`published/{kind}/{name}/{version}/`，按版本快照存储，版本不可变。
  - 发布件的 `.meta.json` 包含多版本引用说明。
- 密钥处理：草稿阶段明文存储；**发布后不展示原始 MCP 配置、Tool 文件、DB 配置**，资源管理只展示名称、版本、描述。
- 有资源管理权限的用户可以删除整个资源或指定版本，以及启用 / 停用。

## 4. 资源检索与上下文

- 资源总量没有上限，**不提供全量列举**：模型用 `resource_search` 按关键词检索，用 `resource_read` 读取正文。
- 技能遵循 Agent Skills 规范（frontmatter + 入口流程 + 子文件一层引用），正文按 token 预算注入，超预算截断并提示继续读取。

## 5. Agent 管理

1. 可以通过组合工具、技能包、MCP 等形成特定领域的智能体。
2. 用户在会话时可以指定使用哪个智能体。

## 6. 本轮不做

- 非 Go 运行时的工具（Python 脚本、CLI 调用、Agent 自建运行环境、依赖快照）暂不实现，后续单列板块。
